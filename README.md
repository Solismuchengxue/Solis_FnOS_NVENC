# Solis fnOS NVENC

为特定 **Tesla P4 / R535** 环境提供飞牛原生影视的 NVENC 兼容方案。通过 SSH 编号菜单完成环境检查、源码构建、补丁安装、开机检查、暂停和卸载，并保留恢复点。

工具版本：0.1.1，`main` 包含 fnOS 1.2.0800 适配；标签 [v0.1.1](https://github.com/Solismuchengxue/Solis_FnOS_NVENC/tree/v0.1.1) 保留原 1.2.0701 兼容清单。源码通过仓库和 Git 标签分发，不单独维护 GitHub Release。

**当前支持范围有限。** 1.2.0800 已通过当前工具的一次整机重启、自动加载及新开机实际恢复；自生成 Main8／Main10 SDR、Main10 手选有效外挂 SRT／ASS 均在所测单路 720p、一次跳转及当次人工确认范围内通过。完整卸载与同版本离线重装已通过；字幕自动选择问题保留，其他格式未验证，完整原版功能对等仍失败，7 天稳定性仍由用户观察，详见[验收报告](docs/installer_report.md)。

## 适用环境

| 项目 | 要求 |
| --- | --- |
| fnOS | 1.2.0800，Debian 12，x86_64，glibc 2.36；旧标签 v0.1.1 对应 1.2.0701 |
| GPU | GRID P4-4Q |
| NVIDIA 驱动 | R535，535.309.01，NVENC API 12.1 |
| 影视组件与依赖 | 与[运行身份合同](metadata/runtime_profile.json)中的 13 项保护文件、50 项外部依赖一致 |
| 宿主工具 | Git、Bash、Python 3.11+、Docker、sudo、systemd、readelf、ldd、nvidia-smi |
| 构建资源 | 至少 8 GiB 可用空间；容器资源上限为 2 CPU、4 GiB 内存 |
| 首次构建网络 | 能访问 FFmpeg、GitHub、Docker Hub 和 Debian snapshot |

已有 NVIDIA 驱动和许可须正常可用。本工具不安装驱动、Toolkit 或 License；构建使用当前 NAS 的本地 Docker，不能使用远程 Docker。

同型号不等于同一环境。未知版本或文件身份变化会停止安装；系统、影视或依赖升级后，启动检查也会拒绝注入旧库。

## 首次安装

### 1. 克隆并打开菜单

在 SSH 交互终端执行：

```bash
cd /vol1/1000/ &&
git clone https://github.com/Solismuchengxue/Solis_FnOS_NVENC.git &&
cd /vol1/1000/Solis_FnOS_NVENC/ &&
bash fnos-nvenc.sh
```

仓库根目录就是入口，无需再建 `source/`。已有非空同名目录时，Git 会停止克隆；保留原目录和恢复材料。旧的嵌套布局继续使用原入口，具体更新方式见[维护说明](docs/maintenance.md#源码更新与工具恢复)。

### 2. 检查环境并安装

先选 **1** 检查环境，再选 **2** 安装补丁。

```text
Solis fnOS NVENC  |  v0.1.1
  1. 检查环境与兼容性
  2. 安装补丁（构建、安装、开机检查）
  3. 更新／修复工具
  4. 查看状态
  5. 播放验证
  6. 暂停补丁／恢复
  7. 卸载补丁
  8. 卸载工具
  0. 退出
```

安装可能重启影视服务。先确认所有人已退出播放和转码，包括直接播放；提示时输入 `IDLE`。密码只在 SSH 终端的标准 `sudo` 提示中输入。

首次安装会下载固定源码，校验签名和 SHA256，并在 Docker 中独立构建两次。两次结果都必须匹配固定候选，否则停止。随后保存本次恢复点，安装工具与兼容库，设置开机检查，并核对服务实际加载结果。

首次构建较慢；再次安装相同版本是幂等操作。构建结果保存在 `builds/`，安装输入暂存在 `tmp/`。这些目录不进入 Git，回收条件见[材料管理](docs/maintenance.md#目录与材料管理)。公开安装无需预置维护者的 `artifacts/`。

### 3. 在飞牛影视中选择 GPU

打开 **设置 → 影视服务器 → 设置**：

1. 开启 **启用 GPU 加速转码**。
2. 将 **首选 GPU** 明确选为 **NVIDIA GP104GL [Tesla P4]**。

补丁接入不会代替应用开关。按设备名称选择，不要仅凭设备编号判断。

## 播放与验证

继续使用原来的飞牛影视入口，无需新增网址、账户或端口。

1. 打开影片，选择原生 **720p**。
2. 完成一次跳转并继续播放。
3. 保持播放，在 SSH 菜单选 **5**。
4. 确认这一次声音正常、无明显音画不同步，再输入 `AUDIO_OK`。

工具记录绑定原生服务的真实 GPU 子进程及其候选库映射。菜单 **4** 用于查看工具版本、自动启用设置、实际加载与播放验证状态。

“已加载”只表示库接入；直接播放、缓存命中和历史听感确认都不能代替本次 GPU 播放验证。外挂字幕的有限结论仅覆盖已测素材的客户端显示，未证明服务端字幕烧录。

## 开机自动检查

安装补丁时启用独立的 systemd 启动检查。每次影视服务启动前，重新核对组件、驱动和依赖；这一步无需网络或 Docker。

检查失败时清除本工具的注入环境，保留其他配置并记录原因，让原服务链启动。启动准备与实际加载分别记录；每次开机建立新的恢复点，旧开机状态不能重放。

暂停后自动注入关闭，再次选 **2** 才重新启用。请保留兼容性检查，不编辑身份合同或验证标记放行未知环境。

## 更新与修复

普通 Git 克隆目录按以下顺序更新：

1. 确认无人播放，在已安装工具菜单选 **6** 暂停补丁。
2. 在源码目录更新并打开菜单：

   ```bash
   cd /vol1/1000/Solis_FnOS_NVENC/ &&
   git pull --ff-only &&
   bash fnos-nvenc.sh
   ```

3. 选 **3** 更新／修复工具，再选 **1** 检查。
4. 检查通过后选 **2** 重新启用补丁。

更新采用版本目录和普通 JSON 原子指针，保留上一版与失败材料。更新工具不会自动重新启用补丁。

菜单 **3** 在核对当前开机恢复后，补登身份已核实的既有库、恢复记录和旧工具备份；未知材料保留并列明。私人验收包需要维护者提供独立核实的身份依据，详见[既有安装归属迁移](docs/maintenance.md#既有安装归属迁移)。

当前工具损坏、上一版仍完整时，先确认补丁已暂停，再从保留源码入口执行：

```bash
sudo bash fnos-nvenc.sh restore-tool
```

它只恢复工具指针，保留损坏文件。没有 `.git` 的源码快照不适用 `git pull`，应按[维护说明](docs/maintenance.md#源码更新与工具恢复)处理。

## 暂停与卸载

操作前先确认所有人退出播放和转码。

| 目的 | 菜单操作 | 保留内容 |
| --- | --- | --- |
| 暂时停用 | **6** 暂停补丁／恢复 | 工具、源码、构建材料和恢复记录 |
| 撤销补丁 | **7** 卸载补丁，核对恢复结果 | 已安装工具和恢复记录 |
| 移除工具及自建残留 | 先 **7**，恢复通过后再 **8** | 源码、构建输入和非本工具材料 |

暂停或卸载恢复本次开机的实际基线。如果组件或开机身份已变化，工具只撤销归属明确的自有配置，并提示恢复未验证；保留记录，交给维护者核对。

菜单 **8** 核对当前开机、实际基线和材料身份后，删除已登记的工具版本、兼容库、旧工具备份、安装输入、失效状态及空的自建目录。源码、构建输入、官方影视、驱动和其他用户材料保留；不清理 Docker 缓存或镜像。

出现改动文件、未知材料、符号链接、恢复未验证或消费者不明时，删除前停止并显示路径；只有残留核对通过才报告卸载完成。历史材料不按目录名或新算哈希直接登记。卸载及迁移改进已通过本地隔离验证，尚未更新 NAS 安装版本或做现场卸载，详见[验收报告](docs/installer_report.md#既有安装归属迁移本地验证)。不增加菜单项。

## 命令行入口

安装后的稳定入口：

```bash
sudo bash /opt/solis-fnos-nvenc/tool/runner.sh
```

源码入口也支持直接指定动作：

```bash
bash fnos-nvenc.sh --help
sudo bash fnos-nvenc.sh check
sudo bash fnos-nvenc.sh status
```

`install`、`update-tool`、`verify`、`disable`、`uninstall-patch`、`uninstall-tool`、`build` 和 `restore-tool` 对应安装与维护操作，`--json` 提供结构化输出。

历史 `check/deploy/status/rollback` 命令保留。`deploy` 是临时接入，不设置开机检查，持久补丁启用时不能混用；`rollback` 恢复当次基线。安装后可离线阅读[快速使用说明](docs/quick_start.md)。

## 常见问题

| 现象 | 建议处理 |
| --- | --- |
| 出现 `STOP` | 保存短提示，核对报告和恢复状态；停止反复覆盖、重启或修改校验值 |
| 两次构建不匹配 | 保留输出；两次互相一致但不匹配固定候选，同样停止安装 |
| 升级后补丁未加载 | 启动检查可能拒绝了新组件，核对状态，等待新的适用合同 |
| GPU 没有参与 | 核对影视 GPU 开关和 Tesla P4 选择；重新开始需要转码的播放，再选 **5** |
| 提示字幕不存在或条目无效 | 明确选择本片可用字幕；已知自动选择问题尚未定位，详见[已知问题](docs/installer_report.md#已知问题与待完成验收) |
| 想清理占用空间 | 停用时先 **7**、再 **8** 清理已登记安装材料；构建输出和历史未登记材料按[材料管理](docs/maintenance.md#目录与材料管理)另行核对 |

查看近期服务消息可用 `journalctl -u mediasrv.service -n 100 --no-pager`。提供排障信息时保留必要摘要，避免公开私人原始日志。
