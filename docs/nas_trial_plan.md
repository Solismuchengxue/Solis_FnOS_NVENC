## 连续执行清单与停止门

| 顺序 | 拟执行及证据 | 通过/停止条件 |
| --- | --- | --- |
| 1. 只读预检 | 从本机 SSH config 解析用户指定别名；确认实际 fnOS/CPU/驱动与 NVENC API、官方影视组件依赖/SONAME、mediasrv 主进程及 `/proc/maps`、当前单元与 drop-in/环境来源、无活动播放/转码的空闲窗口 | 目标唯一、权限可用、单库依赖兼容、单服务边界成立；未知/漂移则不变更 |
| 2. 冻结恢复点 | 确认用户当前实际可用版本；记录其库真实路径/SHA、依赖路径、有效配置及各覆盖文件内容哈希、原权限/owner、必要恢复指令；只保存脱敏摘要 | 当前可用基线可重新加载、保持原样，恢复不依赖候选或旧 PID。不能确认则 BLOCKED |
| 3. 候选与临时覆盖 | 新目录暂存本地候选并核对传输 SHA、文件安全/依赖；先准备可审阅的单服务临时 drop-in diff，核对当前所有覆盖的优先顺序，再加载候选 | 只新增本包命名的 `/run` 覆盖，不改已有覆盖/官方库；候选和被保护路径无异常链接/漂移；超范围即停 |
| 4. GPU 短测 | 从明确授权的合法小输入做有限 NVENC H264/HEVC 转码（各最多 30 秒），记录退出、API、输出尺寸/时长及 GPU 编码直接证据 | 实际主进程库映射/SHA 指向候选；仅编码器枚举、CPU 输出或 nvidia-smi 静态截图不算 GPU PASS |
| 5. 原生用户流程 | 一路 720p 播放、至少一次跳转和继续，用户核对声音/同步；可用且合法的 AC4 短输入验证 demux、51.2→目标输出采样率及音频播放 | 每项单独 PASS/FAIL/NOT_VERIFIED；手动继续与自动续播分开记录，代理未听到的项目不冒称听感通过 |
| 6. 收尾恢复 | 无论短测成功或失败，按冻结恢复点移除/退役**仅本包新增**临时覆盖，daemon-reload 并重启 mediasrv；读取新 PID 和实际映射，恢复当前可用配置/库，再由用户核对原流程 | 库/配置身份回到步骤 2 的可用基线，候选不再是活动消费者；不是单凭 restart 返回 0。异常保留证据，禁止扩大修复 |
| 7. 保全与交付 | 比对被保护的官方文件/既有 drop-in/其他服务与容器集合的有界前后证据，整理脱敏报告，清理仅本包已验证自建临时资源 | 保全、当前可用版本恢复和测试结果分别记录；完成后停止 |

现场时限建议为一个不超过 60 分钟的空闲窗口、单路播放/单个 mediasrv，GPU 转码总长不超过 60 秒；可用输入或窗口不足则缩小测试并明确 NOT_VERIFIED，不追加大数据集、并发或稳定性长跑。

## 恢复合同的关键区别

恢复目标是 **步骤 2 确认的当前可用版本**。如果现场当前可用版本是历史候选，试用结束后应恢复它的库映射和有效配置；如果是官方组件，则恢复官方组合。不能把“删除所有兼容覆盖、只加载官方库”当作通用恢复成功。

现有 `rollback_runtime.sh` 针对恢复官方组件，并未真实演练；只有现场基线与其合同完全一致时才可复用。若已有临时兼容覆盖，优先只增加本包独立覆盖，结束只移除本包覆盖，使原可用环境重新生效。执行前须依据现场证据给出精确 diff 与恢复 argv，拒绝符号链接、内容漂移、已有目标冲突和不确定的消费者；不把旧脚本、旧 SHA/PID 或 `/run` 的重启预期当保证。

即使本包各短测通过且恢复成功，full vendor parity、其他格式、并发、跨版本、重启恢复与长期稳定性仍按各自直接证据记录。长期启用或 NAS 重启测试需要另一个明确有限包。
