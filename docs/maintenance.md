# 公开安装器维护说明

本文件维护现行 SSH 菜单的验证、恢复和材料管理条件。用户安装、使用及卸载入口见 [README](../README.md)，当前交付证据见[安装器报告](installer_report.md)。

## 适用合同与构建

首版仅支持 fnOS 1.2.0701 / GRID P4-4Q / R535 535.309.01，以及[身份合同](runtime_profile.json)绑定的 13 项保护文件与 50 项外部依赖。Python 3.11+ 使用标准库；驱动、许可、Docker 等宿主前提由用户现有环境提供。

公开构建消费仓库、[固定公开来源](build_sources.json)及[286 项依赖版本](build_packages.txt)。下载验证大小、SHA256 和签名，依赖与两次干净编译仅在当前 Linux 的本地 Docker 中进行；不使用历史私人镜像或候选作为构建输入。两次输出均须匹配既定候选，不修改合同放行。nonfree 库与环境镜像只作本地私人保存。

## 构建目录与补丁职责

`build/` 保存随 Git 发布的两个现行容器构建脚本；`builds/` 保存每次公开构建生成的材料，被 Git 忽略。`artifacts/` 是维护者本地保存的固定源码、当前库和基线库，不与源码脚本混放。公开克隆不需要预置 artifacts；本地离线材料核验仍读取保存的来源与基线。

| 补丁 | 用途 | 公开单库构建 |
| --- | --- | --- |
| [ac4_decoder.patch](../patches/ac4_decoder.patch) | 增加 AC4 decoder/parser 实现及注册；保留上游声明 | 按固定顺序先应用 |
| [ac4_parser_type.patch](../patches/ac4_parser_type.patch) | 将 parser 声明从 AVCodecParser 修正为 FFCodecParser | 随后应用，缺少会阻断构建 |

NVENC API12.1 兼容由固定头文件与构建配置实现。仅保留上述两份正式补丁，源码身份和应用顺序固定。AC4 demux 实验补丁及配套探针、CPU／音频对照、WAV 检查和实验测试已退役。

## 本地验证入口

在现有 Linux 源码工作目录执行不依赖私人归档的测试：

```bash
python3 -B -m unittest discover -s tests -p 'test_nvenc_*.py'
bash -n fnos-nvenc.sh
bash fnos-nvenc.sh --help
```

现行 tests 只保留安装器、运行控制、消费者与文件保护测试及所需替身。卸载消费者核对由 `nvenc_install.py` 执行，运行进程与实际库映射核对由 `nvenc_runtime.py` 执行；旧 SSH/FIFO 传输检查器及配套测试已退役。`verify_materials.py` 只读核对材料清单中的本地源码、基线库和必要检查记录；公开克隆不以它作为安装前提。旧媒体实验入口不再提供。

隔离文件树和替身服务测试只证明本地文件、事务及拒绝行为；parser、构建、实际库映射、人工听感和 NAS 恢复是不同证据层。文档维护检查相对链接、非空文件、安装载荷存在、忽略规则和 `git diff --check`，不因整理文档重新运行媒体、构建或 NAS 验收。

## 更新与故障恢复

工具使用 root 所有版本目录、SHA256 清单和普通原子 JSON 指针，不使用符号链接。更新保留上一版与失败目录；损坏时从保留源码入口运行 `sudo bash fnos-nvenc.sh restore-tool`，独立验证完整上一版后切换指针。

服务启动前先清空本工具注入，验证组件并持久保存本 boot 恢复点后才写 `/run` 环境文件。启动准备与实际加载分开记录；重启前按事务释放锁，避免钩子与安装器互等。未知组件、身份漂移或旧 boot 不重放历史状态，不自动重启未知组合。

服务变更前重新确认所有播放和转码退出，包括直接播放。暂停、卸载先恢复当次基线并核对实际结果；身份变化时撤销明确归属本工具的配置，保持“恢复未验证”。文件已改动、恢复未闭合或消费者不明时停止删除并保留材料。

应用设置与库接入分别核对：在影视服务器设置开启 GPU 加速，并按设备名称选择 Tesla P4。设备编号、应用开关、启动准备、服务库映射与实际 GPU 子进程不是同一证据；未出现绑定原生服务的 GPU 消费者时，不计入播放通过。变更首选设备后重新开始本轮播放和声音确认。

## 目录与保留

| 位置 | 用途与保留条件 |
| --- | --- |
| `/vol1/1000/Solis_FnOS_NVENC/` | 源码根目录与菜单入口；当前 NAS 发行快照已按用户要求移平，仍没有 `.git`。其他既有嵌套布局不自动迁移 |
| 项目 `builds/`、`tmp/` | 构建结果和当次暂存，Git 忽略；确认必要材料已独立保留、身份完整且无消费者后，才判断可回收项 |
| `/opt/solis-fnos-nvenc/` | 已安装工具版本和单库；清单、所有权及消费者核对后，仅卸载本工具身份匹配的自建文件 |
| `/var/lib/solis-fnos-nvenc/` | 持久事务与恢复记录，按 boot 区分，默认保留 |
| `/run/` | 本工具启动环境等临时状态；不能用旧 boot 的状态恢复新 boot |
| 本地 `artifacts/` | 只留 `sources/` 的四项公开源码缓存、`runtime_bundle/` 的当前库和身份文件，以及 `candidate-lib/` 的基线库；共七文件，Git 忽略 |

维护工作包可暂存经固定提交核对的发行源码快照；快照没有 `.git`，不按普通克隆目录执行 `git pull`。当次目录、输入身份与接入状态集中由[安装器报告](installer_report.md)维护，不能把源码暂存或隔离测试视为正式工具已更新。

`tmp/install-input-*` 是安装／更新生成的独立输入副本，包含源码载荷、候选库和身份文件；成功后工具仍保留它们，重复操作会累积。已安装工具从 `/opt/solis-fnos-nvenc/tool/` 的版本目录运行，不从这些副本加载。`tmp/` 还可能含源码传输包及验收恢复材料，须逐项核对用途、独立恢复材料与消费者后决定回收。目录不存在时不影响现有工具运行；下一次安装／更新可能重新创建。

获当次明确授权后，NAS 暂存通过 fnOS 文件管理器“移至回收站”，本地暂存通过 Windows 回收站回收；保留正常还原能力，不永久删除或清空回收站。NAS 在回收站中按原路径 `我的文件/Solis_FnOS_NVENC/tmp` 找到目录并选择“还原”，本地按原始项目路径找到 `tmp` 并还原。当前回收结果由[安装器报告](installer_report.md)维护。

2026-10-11 新版有限接入验收完成，当前保留 0.1.1 工具与自动启用。维护时优先从 `sudo bash /opt/solis-fnos-nvenc/tool/runner.sh` 进入；源码快照及旧工具、基线库和当前开机恢复记录保留。工作区新增的使用说明没有直接覆写 NAS 清单文件，安装载荷仍是已发布提交的原字节。

本项目采用原生 mediasrv 辅助工具，不是 Compose 服务；源码与构建根、`/opt` 安装、`/var/lib` 恢复和 `/run` 临时状态是本项目明确的目录例外。当前来源与边界见[来源记录](source_and_evidence.md)；这些目录约定不推广为其他项目规范。

没有自动删除构建、旧版本或恢复记录的任务。不能把整个项目 `tmp/` 一律当作垃圾；本地清理须核对当次授权、实际路径、内容变化、ReparsePoint 和消费者，确认必要材料完整后使用 Windows 回收站。不为已完成过程另建日志、审计 ZIP 或重复交付包；共享文档保留必要结论与限制。NAS 暂存与恢复材料按现场合同处理，不从本地整理推出远端清理权限。

2026-10-11 本地过程材料已退役，包括旧冻结镜像归档及 ID、重复 run1/run2 库、旧试验记录包。公开构建由固定公开来源准备新的 Docker 环境，不读取这些材料；当前恢复读取 NAS 自身 `/var/lib/solis-fnos-nvenc/` 状态，不读取本地旧试验归档。该次本地整理未修改 NAS 工具、基线库或恢复记录；之后另行获批的现场结果见安装器报告。

现行代码仅保留安装、构建、恢复及必要校验。旧 AC4、多库、CPU／音频对照实验补丁、脚本和测试已回收；正式构建输入、当前候选、基线库及身份合同保持不变。

## 日志、许可与验证限制

动作结果显示在终端，启动消息由 systemd 接收。可用 `journalctl -u mediasrv.service -n 100 --no-pager` 查看近期消息；不公开私人原始日志。恢复历史、构建结果和备份会累积，工具不替用户修改系统日志轮转或自动回收空间。
